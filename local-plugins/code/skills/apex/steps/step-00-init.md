# Step 0: Initialization

Parse flags, handle resume, run enabled sub-steps, then proceed to step-01. Init never blocks and never starts analysis or implementation.

<defaults>
## Default Configuration

**Edit these values to change default behavior. Flags always override defaults.**

```yaml
auto_mode: false        # -a: Skip confirmations, use recommended options
examine_mode: false     # -x: Adversarial review
save_mode: false        # -s: Save outputs to .claude/output/apex/
test_mode: false        # -t: Test creation and runner steps
verify_mode: false      # -v: Launch app and verify feature works
economy_mode: false     # -e: No subagents, save tokens
branch_mode: false      # -b: Verify not on main, create branch if needed
pr_mode: false          # -pr: Create pull request at end (enables -b)
interactive_mode: false # -i: Configure flags interactively
tasks_mode: false       # -k: Task breakdown after plan
teams_mode: false       # -m: Agent Teams parallel execution (enables -k)
```
</defaults>

## 1. Parse flags

Load the defaults above, then apply flags from user input. Lowercase enables, UPPERCASE disables: `-a`/`-A`, `-x`/`-X`, `-s`/`-S`, `-t`/`-T`, `-v`/`-V`, `-e`/`-E`, `-b`/`-B`, `-k`/`-K`, `-m`/`-M`, `-pr`/`-PR`. Long forms: `--auto`, `--examine`, `--save`, `--test`, `--verify`, `--economy`, `--branch`, `--tasks`, `--teams`, `--pull-request`, `--interactive`, and `--no-<name>` to disable.

Implications: `-pr` also sets branch_mode=true; `-m` also sets tasks_mode=true.

`-r <id>` (or `--resume <id>`) sets `{resume_task}`. Everything remaining is `{task_description}`.

Derive `{feature_name}` = kebab-case of the description without number prefix ("add user authentication" → "add-user-authentication"). `{task_id}` (numbered, e.g. `01-add-user-authentication`) is generated by the setup script in step-00b-save.

## 2. Resume mode — only if {resume_task} is set

1. `ls .claude/output/apex/ | grep "^{resume_task}"`
2. Exact match → read its `00-context.md` to restore state variables, find the last completed step from the progress table, load the next incomplete step. Do NOT continue with fresh init.
3. Partial match (e.g. `-r 01`) → single hit: use it; several: list them and ask which.
4. No match → list available tasks and ask for the correct ID.

## 2b. Ticket mode — only if the input names a ticket or a feature

The input is a ticket reference when it is a path to a ticket file, an issue number or URL, or the slug or folder of a feature that has tickets. A plain sentence is not one: skip this section.

The tracker record is the file that the `### Issue tracker` section of `CLAUDE.md`, `CLAUDE.local.md` or `AGENTS.md` points to, which may sit outside the repo; without such a section, it is `docs/agents/issue-tracker.md`. If it exists, follow its operations; otherwise specs and tickets are local files under `.scratch/<feature-slug>/` (`spec.md`, `issues/<NN>-<slug>.md` with `Status:` and `Blocked by:` lines).

1. Resolve the ticket. A feature with no ticket number means its next startable ticket: the first open one whose blockers are all resolved. If none is startable, say which tickets are open and what blocks each, and stop.
2. Read the ticket and its spec in full, and the `## Report` of each ticket that blocks it: it says what the earlier work learned. State the ticket's title in one line.
3. Claim the ticket (local files: set `Status: claimed` and save) before any other work, so a parallel session skips it.
4. Set `{ticket_ref}`, `{spec_ref}`, `{task_description}` = the ticket title, and `{run_dir}`: for local files `<feature folder>/runs/<NN>-<slug>/`, beside `issues/`, created now; on a tracker, the folder its "Working notes" section names.

The ticket's acceptance criteria become `{acceptance_criteria}`. The spec's implementation and testing decisions are settled: follow them, do not reopen them. If the ticket or the spec cannot be built as written, stop and say why instead of improvising.

## 3. Optional sub-steps (in this order, if enabled)

- interactive_mode → load `step-00b-interactive.md` (reconfigure flags, return here)
- branch_mode → load `step-00b-branch.md` (sets `{branch_name}`)
- economy_mode → load `step-00b-economy.md` (behavior overrides)
- save_mode → load `step-00b-save.md` (sets `{task_id}` and `{output_dir}`)

## 4. Summary and proceed

Show one line `✓ APEX: {task_description}`, one compact table with every flag variable and `{task_id}`, then `→ Analyzing...` and load step-01 immediately. No parsing logs, no explanations, no confirmation.
